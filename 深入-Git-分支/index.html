深入 Git 分支

发表于2026-06-02|更新于2026-06-03|Git
|浏览量:

文中图片内容均来自 Git 官方文档，我只不过作了一些改动，更多详细内容请看 Git 官方的 Git Branching

为了真正理解 Git 处理分支的方式，我们需要知道 Git 是如何保存数据的。

假设现在有一个工作目录，里面包含了三个将要被暂存和提交的文件：README、test.rb 和 LICENSE。

  1. git add README test.rb LICENSE：暂存操作会为每一个文件计算校验和（使用 SHA-1 哈希算法），然后会把当前版本的文件快照保存到 Git 仓库中 （Git 使用 blob 对象来保存它们），最终将校验和加入到暂存区域等待提交。

  2. git commit -m 'The initial commit of my project'： 进行提交操作时，Git 会先计算每一个子目录（本例中只有项目根目录）的校验和， 然后在 Git 仓库中这些校验和保存为树对象。随后，Git 便会创建一个提交对象，它除了包含提交时输入的信息、作者姓名和邮箱等，还包含指向这个树对象（项目根目录）的指针。

现在，Git 仓库中有五个对象：三个 blob 对象（保存着文件快照）、一个树对象（记录着目录结构和 blob 对象索引）以及一个提交对象（包含着指向前述树对象的指针和所有提交信息）。

做些修改后再次提交，那么这次产生的提交对象会包含一个指向上次提交对象（父对象）的指针。

Git 的分支，其实本质上仅仅是指向提交对象的可变指针。

Git 的默认分支是 master。

回到上面的例子，在多次提交操作之后，master 指向最后那个提交对象，master 分支会在每次提交时自动向前移动。

Git 是怎么创建新分支的呢？

Git 创建新分支时仅仅是创建了一个可以移动的新的指针。

这会在当前所在的提交对象上创建一个指针。

Git 又是怎么知道当前在哪一个分支上呢？

Git 维护一个名为 HEAD 的特殊指针，指向当前所在的本地分支。

你可以在不同分支间不断地来回切换和工作，并在时机成熟时将它们合并起来。

总结：由于 Git 的分支实质上仅是包含所指对象校验和（长度为 40 的 SHA-1 值字符串）的文件，所以它的创建和销毁都异常高效。

创建一个新分支就相当于往一个文件中写入 41 个字节（40 个字符和 1 个换行符）。

由于每次提交都会记录父对象，所以寻找恰当的合并基础（译注：即共同祖先）也是同样的简单和高效。 这些高效的特性使得 Git 鼓励开发人员频繁地创建和使用分支。
